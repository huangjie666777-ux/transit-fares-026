# 离线公交换乘规划器

基于 React + TypeScript + Vite 的离线公交换乘规划器。系统**只按班次时刻**（而非站点距离）计算行程，全部计算在浏览器本地完成，不接入任何地图或在线交通服务。

## 启动方式

使用已准备好的 Node.js 22.19.0 和 npm 10.9.3，可直接运行：

```bash
npm ci          # 首次或依赖损坏时
npm run dev     # 启动开发服务器，默认 http://localhost:5173/
```

其他命令：

```bash
npm test        # Vitest 单元测试（时刻搜索算法 + 路网校验）
npm run build   # 类型检查 + 生产构建，产物在 dist/
```

## 数据格式

路网为一个 JSON 对象，包含 `stops` 与 `trips`：

```json
{
  "stops": [
    { "id": "A", "name": "中央公园", "minTransferMinutes": 3 }
  ],
  "trips": [
    {
      "id": "T1",
      "routeName": "1路 直达快线",
      "stops": [
        { "stopId": "A", "arrive": null, "depart": 360 },
        { "stopId": "B", "arrive": 380, "depart": 385 },
        { "stopId": "C", "arrive": 410, "depart": null }
      ]
    }
  ]
}
```

- `stops[].id`：站点唯一 ID；`name` 为显示名；`minTransferMinutes` 为该站中途换乘所需的最短分钟数（非负整数）。
- `trips[].id`：班次唯一 ID；`routeName` 为线路名；`stops` 按行驶顺序排列。
- 时刻是**运营日零点起的整数分钟**：360 = 06:00；允许跨午夜，1500 显示为 `01:00（+1日）`。
- 首站 `arrive` 可省略（`null`），末站 `depart` 可省略（`null`），省略时自动取同侧时刻。
- 校验规则：站点/班次 ID 不可重复；停站必须引用已存在的站点；时刻不可为负；同站发车不得早于到达（倒退）；相邻停站行驶时间必须严格为正。
- 导入校验失败时会在页面列出形如 `trips[0].stops[2].arrive` 的精确定位，且**保留原路网不变**。

## 票价方案格式

票价方案与路网**分开管理**，是另一个 JSON 对象，包含 `singleFares` 与 `passes`：

```json
{
  "singleFares": { "T1": 300, "T2": 400 },
  "passes": [
    {
      "id": "P1",
      "name": "2路/4路 150分钟联票",
      "price": 600,
      "validMinutes": 150,
      "trips": ["T2", "T4"]
    }
  ]
}
```

- `singleFares`：以班次 ID 为键的单次票价，金额为**非负整数分**。
- `passes[].id`：联票唯一 ID（不可重复）；`name` 为显示名；`price` 为非负整数分；`validMinutes` 为**正整数**有效分钟数；`trips` 为适用班次 ID 列表（不能为空、不可重复）。
- 校验规则：联票 ID 重复、引用未知班次、金额或时长非法都会列出形如 `passes[0].price` 的精确定位；整份导入失败时**保留当前票价方案**。旧版不含票价的路网 JSON 照常可用。

## 票价计算规则

- 行程由查询条件唯一确定，**不因价格改变路线**；票价只在既定行程的乘车段上计算。
- 每个乘车段上车时可选择：购买该班次的单次票，或使用一张已购买且当时有效的联票。同一班次经过中间站只计一段。
- 联票在**首次使用的上车时刻**购买并生效，有效期含开始、不含结束（`[购买时刻, 购买时刻 + validMinutes)`），按运营日分钟连续计时，**跨午夜不重置**。
- 有效期内一张联票可覆盖多个适用班次，中间遇到不适用班次可跳过、之后继续使用；同种联票可重复购买，各自独立计时。
- 报价求覆盖全部乘车段的**最低总价**；总价相同优先购票张数少，仍有平局则按固定顺序稳定选择。
- 报价列出每张票的价格、购买时刻、到期时刻与覆盖的乘车段，并给出逐段单买总额与节省金额。
- 任一乘车段所属班次缺少单次票价时，明确提示未配置的班次，**不把缺失当免费**；零乘车行程总价为零；无可行行程时不生成报价。
- 查询条件、行程或票价方案变化时旧报价立即失效；编辑区中未点击“导入编辑区 JSON”确认的内容不参与计算。

## 票价方案操作

1. “票价方案”区域默认载入**联票更省钱示例**（2路/4路 150分钟联票 6.00 元，A→F 行程逐段单买 7.50 元，联票省 1.50 元）。
2. 可点击“单次票更省钱示例”对比（联票 9.00 元，单买 7.50 元更划算）。
3. 可直接在编辑区修改 JSON 后点击“导入编辑区 JSON”，或从本地文件导入；点击“导出当前方案 JSON”可下载当前生效方案。

## 核心操作

1. 页面默认载入内置示例（含直达、一次换乘、跨午夜三类班次）。可直接选择起点、终点、出发时刻（`HH:MM`，小时支持到 47 以查询次日）和最多换乘次数。
2. 点击“查询最早到达”，结果按乘车段展示线路、班次、上下车站及到发时刻，并列出首段候车时间、每段换乘等待（含该站最短换乘时间）、总耗时与换乘次数。
3. 选路规则：最早到达优先；到达相同则换乘次数少者优先；再相同则按班次 ID 序列字典序选择。同一班次继续乘坐不计换乘；首次上车不加换乘时间；中途换乘必须满足 `下车时刻 + 该站最短换乘时间 ≤ 下一班发车时刻`（恰好相等允许登车）。
4. 站点示意图按班次展示停站与到发时刻，查询后高亮实际经过的站点。起点终点相同时展示零乘车行程；无可行班次时给出明确说明，且不会残留上次结果。
5. 在“路网数据”区域可直接编辑 JSON 后导入，或选择本地 JSON 文件导入；也可随时点击“载入示例”恢复。

## 代码结构

- `src/types.ts`：数据类型。
- `src/sampleData.ts`：内置示例路网。
- `src/validation.ts`：JSON 解析与带定位的校验。
- `src/planner.ts`：基于标签（Pareto 前沿）的最早到达搜索，保留“到达较晚但可能更优”的乘车状态。
- `src/fares.ts`：票价方案校验与最低费用计算（按乘车段动态规划，状态含已购未过期联票）。
- `src/App.tsx` / `src/style.css`：查询表单、结果展示、示意图与导入界面。
